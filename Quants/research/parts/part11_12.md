## PART 11 — THE AI/ML SYSTEM

### 11.1 Inputs, features, predictions, state, decisions, rewards

| Element | Content |
|---|---|
| **Inputs** | Job telemetry (GPUs, mode, progress, checkpoint age, node health), inference telemetry (req/s, tokens, p50/p99 TTFT/TPOT, replicas), power (per rack, site), thermal (rack/coolant temps, supply temp, flow), battery SOC, grid (price now, day-ahead prices, event notices, carbon intensity), weather, calendar. |
| **Features** | Lags (5 min … 24 h), rolling stats, hour-of-day/day-of-week, holiday flags, day-ahead price, weather forecast, deploy/event flags; per-job profile vectors (model size, parallelism, batch, seq len, GPU type). |
| **Predictions** | (1) Inference demand quantiles per service, 5 min–2 h ahead; (2) real-time price residual quantiles vs day-ahead; (3) per-job $(p_{jk}, \rho_{jk})$ tables; (4) thermal parameters $(\alpha,\beta,\gamma)$ and residual; (5) optional failure hazard per node. |
| **State** (for MPC) | Work remaining and mode per job, replicas per service, rack temperatures, SOC, event status, current power. |
| **Decisions** | Mode per job, replicas/config per service, supply setpoint, battery power (L1); DR commitment (L0). |
| **Reward / cost** | Negative of the Part-10 objective per step (used identically by MPC and the RL baseline for fairness). |
| **Optimization layer** | L0/L1 MILPs (HiGHS); BO for hyper-parameters. |
| **Feedback loop** | Every 5 min: telemetry → state estimate → forecasts → solve → actuate → observe; daily: retrain forecasters, re-identify thermal model, update job curves from observed throughput. |

### 11.2 Methods compared, and why each belongs

| Method | Role in HEADROOM | Why it belongs (or not) |
|---|---|---|
| **Gradient boosting (LightGBM) with quantile loss** | Demand and price-residual forecasting | Tabular, small data, fast to retrain daily; quantiles feed chance constraints directly; strong baseline in load forecasting. |
| **Probabilistic/seasonal baselines** (seasonal-naive, ETS) | Reference forecasters | Required to show skill; Azure traces have strong diurnal seasonality. |
| **Temporal Fusion Transformer / N-BEATS** | Optional comparison | Only if LightGBM underperforms; not default for a student timeline. |
| **Supervised surrogate (GBDT/MLP)** for $(p, \rho)$ curves | Generalize DVFS curves across job types | Profiling every job is expensive; a surrogate over (model size, parallelism, batch, GPU) fitted on Zeus/Perseus/NLR data predicts the curve for new jobs; refined online from observed throughput. |
| **Grey-box system identification** (least squares / Kalman) | Thermal RC parameters | Physics structure + data → interpretable, few parameters, robust; GP residual optional. |
| **Model predictive control** | Core decision engine | Known linear dynamics + hard constraints + discrete decisions + forecasts = the textbook MPC setting; explainable schedules. |
| **Bayesian optimization** | Tuning MPC weights/horizon against long simulations | Expensive black-box objective, few dimensions (5–8): BO is the right tool. |
| **Reinforcement learning (PPO)** | Baseline policy | Appropriate as a *learned heuristic* on the simulator; expected to violate constraints or need heavy shaping — an informative comparison, not the core. |
| **Imitation learning** | Stretch: distill MPC into a fast MLP policy | Enables sub-second decisions if a real deployment needed them; also tests generalization. |
| **Graph neural networks** | Not used | Topology-aware placement is out of scope; the coarse network model does not need a GNN. |
| **Digital twin** | Evaluation and training environment | Only way to test hyperscale scenarios without proprietary access. |

### 11.3 Forecasting evaluation
Pinball loss at q∈{0.5, 0.9, 0.95}, PICP coverage, MAPE at 5/30/120-min horizons; ablation of MPC cost vs forecast skill ("value of forecasting").

## PART 12 — THE DIGITAL TWIN: *HeadroomSim*

### 12.1 Cluster (default configuration, parametric)
- **Compute:** 2,048 H100-class GPUs in 256 nodes (8 GPUs, 700 W TDP, ~10.2 kW/node), 32 liquid-cooled racks × 8 nodes (~85 kW/rack IT). **Heterogeneous option:** add 16 GB200 NVL72 racks (1,152 GPUs, ~120 kW/rack, 72-GPU NVLink domains).
- **Site:** IT ≈ 2.7 MW (4.6 MW with NVL72 option); PUE model 1.12–1.35 depending on supply temperature and weather; site cap 3.2 MW with a *flexible tranche*: firm 2.4 MW + 0.8 MW curtailable within 15 min for ≤100 h/year (mirrors the Duke 1% curtailment regime and SB6-style obligations).
- **Battery (optional):** 1 MWh / 1 MW, η = 0.92.

### 12.2 GPU power model
- Per-GPU power = idle (≈80–100 W) + dynamic component from mode table; per-node overhead 1.2 kW; modes for training jobs: {suspend, 350 W, 450 W, 550 W, 700 W} with throughput ratios fitted from Zeus/Perseus (e.g., ≈0.62/0.80/0.93/1.00 for compute-bound; flatter for memory-bound). Inference replicas: $a_{s,c} + b_{s,c}\cdot$load, prefill-heavy vs decode-heavy variants.
- **Fast waveform (for realism, not control):** within each 5-min step, training power oscillates with iteration period (2–10 s) and amplitude 20–45% of rack power, sampled from the NLR 0.1-s H100 profiles; used to compute ramp/peak metrics and to check that hardware smoothing assumptions hold.

### 12.3 Workloads
- **Training jobs:** arrivals and sizes from Alibaba PAI / Acme distributions (heavy-tailed: 8–1,024 GPUs; durations hours–weeks; ~60% of GPU-hours in the top 10% of jobs); classes: pre-training (rigid, high $v_j$), fine-tuning/RL post-training (elastic, medium $v_j$), evaluation/batch (flexible, low $v_j$, deadline-only).
- **Inference services:** 8–12 services with demand shaped from Azure LLM traces 2023/2024 (5-min aggregation; diurnal peak-to-trough ≈ 2–4×), token-length distributions from the traces; SLOs: TTFT p99 ≤ 1 s, TPOT p99 ≤ 50 ms (capacity per replica from published vLLM/TensorRT-LLM benchmarks).
- **Arrival distributions:** non-homogeneous Poisson for training submissions (hour-of-day intensity from traces); inference request arrivals replayed from traces with scaling.

### 12.4 Thermal and cooling
- Rack RC model (2 states: coolant/cold-plate and chip), parameters from published lumped models and NVIDIA/OCP specs (45 °C inlet capable); CDU with N+1; **fault scenario:** one CDU loses 50% capacity → β_r doubles for affected racks.
- Cooling power: dry cooler + trim chiller; COP as a function of (supply temp − ambient wet-bulb) from public manufacturer curves; weather from NOAA for three sites (Phoenix, Northern Virginia, Dublin).
- Water: optional evaporative mode with WUE model for the water-vs-energy scenario.

### 12.5 Network (coarse but present)
- Two-tier rail-optimized Clos; α–β model for all-reduce time as a function of job size and number of concurrently resizing jobs; congestion penalty when spine utilization > 70%; migration = checkpoint transfer time at 25 GB/s.

### 12.6 Failures
- Per-GPU Weibull hazard calibrated to Meta/Llama-3 rates (~1 unexpected failure per 3 h per 16k GPUs → ≈1 per 24 h for 2k GPUs); 5% "lemon" nodes with 5× hazard; restart cost = checkpoint reload + re-warm (5–15 min); optional link: +20% hazard for GPUs above 80 °C (sensitivity parameter, not a claim).

### 12.7 Electricity prices and grid events
- 5-min real-time and day-ahead LMPs for ERCOT (North Hub), PJM (Dominion zone) and CAISO (NP15) for 2024–2025 via `gridstatus`; delivery/demand charges from public tariffs; DR archetypes: (A) *event-based* (ERS/ELRP-like: 24 h notice, 15-min ramp, 2–4 h events, ~20–40 per year, $/MWh payments), (B) *ramp/cap-based* (SB6/AESO-like: ≤10 MW/min, emergency curtailment with 30-min notice); carbon intensity from Electricity Maps.

### 12.8 Baselines vs proposed
| Policy | Description |
|---|---|
| **B0 Static-cap kill** | Site cap enforced by killing/pausing lowest-priority jobs; no DVFS; replicas fixed. |
| **B1 Uniform capping (nvPAX-like)** | Fair per-GPU power cap scaled to meet the envelope; no throughput model. |
| **B2 Priority rules (Emerald/DSX-Flex-like)** | Ordered levers: pause batch → cap fine-tuning → cap pre-training → scale replicas; static thresholds. |
| **B3 Day-ahead batch shifting (Google VCC-like)** | Hourly caps on flexible work; no intra-hour response. |
| **B4 Perseus-only** | Bloat removal per job, then B2 rules. |
| **B5 RL (PPO)** | Learned policy on the Gymnasium wrapper with the same reward. |
| **H-D HEADROOM deterministic MPC** | Part-10 MILP with point forecasts. |
| **H-S HEADROOM stochastic MPC** | Quantile-robust or scenario-based. |

**Measurable outputs per run:** every metric in Part 13, logged at 5-min resolution, with seeds and configs for reproducibility; Pareto frontiers from ε-sweeps.
